Tests cover strict whole-peso input and exact centavos, maximum/zero bounds, TLV boundaries and duplicates, nested templates, CRC's known `123456789 → 29B1` vector, amount insertion/replacement and `01=12`, preservation of routing and unknown fields, recipient masking, unsupported fallback and the empty production allowlist. Phone cases include both formats, separators, adjacent digits, invalid lengths, deduplication, multiple candidates and no-number text. Service and UI tests cover hydration/corruption/missing images, serialized failed writes, cancelled/superseded imports, staging cleanup, retention of previous recipients, malformed/multiple/unreadable image results, gallery denial, sharing availability, clipboard failure and copy-before-launch failure.

The export UI test starts capture, changes the active recipient and amount, and verifies the displayed/captured card keeps the frozen original payload and amount until export finishes. Zero and invalid input disable exports; invalid input stays visible and disables adjustments.

## Independent QR decode

Passed: `npm run verify:qr` renders the actual `PaymentCard` and `react-native-qrcode-svg` QR component. Test adapters translate its SVG host primitives to SVG markup; Sharp rasterizes that output to PNG, and independent jsQR decoding must equal the exact supplied synthetic payload. The generated PNG was also visually inspected for black/white contrast and quiet zone.

The synthetic fixture is explicitly TEST ONLY. This validates the renderer's payload output, not a real payment destination. `artifacts/synthetic-renderer.png` and `.svg` can be regenerated by the test and are ignored by Git. The PNG in this check contains the QR region; native view-shot capture of the complete payment card, Android display scanability and gallery/shared-image decoding still require a device. Labels and export snapshot consistency are covered separately by the UI test.

## Dependency advisory result

`npm audit` reported **65 dependency findings: 49 high and 16 moderate**, including propagated findings through the Expo/React Native/Jest dependency trees. This is separate from the passing SDK compatibility checks. The complete local report is in ignored `artifacts/npm-audit.json` and can be regenerated with `npm audit --json`.

Suggested fixes for the affected direct packages include changing SDK/framework major versions or downgrading to versions outside SDK 57's supported set. Those changes were not forced into this Expo Go app. Dependency advisory remediation remains open; passing type checks and bundling do not establish that the dependency tree is vulnerability-free.
